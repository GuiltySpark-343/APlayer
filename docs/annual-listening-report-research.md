# 年度听歌报告调研与改进建议

## 1. 调研结论

QQ 音乐、网易云音乐、Spotify Wrapped 等产品的年度报告，核心都是记录逐次播放事件，再按年份聚合，而不是只保存一首歌的累计播放次数。

常见报告维度包括：

- 全年播放次数、收听时长、听歌天数
- 播放次数或收听时长最高的歌曲、歌手、专辑
- 听过的歌曲、歌手、专辑数量
- 最常听月份、日期、小时段和星期
- 完整听完比例、跳过比例和重复播放行为
- 新增歌曲数量，以及新增歌曲中真正听过的数量
- 主动选择与自动播放的差异

## 2. APlayer 当前缺口

现有 `History` 只记录歌曲的累计 `play_count` 和 `last_play`，没有以下信息：

- 单次播放的开始和结束时间
- 实际收听时长
- 播放完成比例
- 播放来源
- 播放当时的歌曲信息快照
- 歌曲加入媒体库和首次收听时间

因此，年度统计应从功能上线后开始积累，无法从旧的累计次数中还原完整历史。

## 3. 建议的统计口径

### 有效播放

歌曲收听比例不足总时长 10% 时忽略：

```text
listenRatio < 0.1 -> 不计入有效播放
```

超过 10% 后计入一次有效播放，并按实际收听比例累计收听积分：

```text
playScore = min(listenedMs / durationMs, 1.0)
```

建议将“播放次数”和“收听积分”分开：播放次数保持整数，收听积分允许小数。例如播放 20 次、完整听完 12 次、累计收听积分 15.7。

### 完整播放

播放自然结束，或收听比例达到 90%，记为完整播放。这个阈值可在实现时设为常量，后续再根据实际使用情况调整。

### 主动播放

记录播放来源，区分用户主动选择和队列自动播放：

- `SEARCH_CLICK`：搜索结果点击
- `LIBRARY_CLICK`：歌曲库、专辑或歌手页面点击
- `PLAYLIST_CLICK`：播放列表点击
- `QUEUE_AUTO`：随机播放或队列自动切换
- `RESUME`：恢复上次播放
- `EXTERNAL_INTENT`：其他应用打开歌曲

主动播放次数可按来源聚合，搜索点击次数作为一个独立指标。

### 新增歌曲

歌曲需要区分两个时间：

- `addedAt`：首次被扫描或导入音乐库的时间
- `firstPlayedAt`：第一次产生有效播放事件的时间

这样可以统计某年新增了多少歌曲，以及新增歌曲中有多少真正被收听。

### 跨平台标识

播放记录未来需要和电脑端合并，因此不能把 Android MediaStore 的 `audioId` 当作跨平台主键。建议使用稳定的 `canonicalId`，并同时保留来源 URI、文件哈希和路径提示作为辅助信息。所有事件都应包含全局唯一的 `eventId`、固定的 `deviceId` 和 `schemaVersion`。时间统一使用 UTC 的 ISO 8601 格式，导出格式优先支持一行一条事件的 JSONL，便于增量同步和按 `eventId` 去重。

## 4. 第一版建议报告内容

- 全年有效播放次数
- 全年收听时长
- 全年听歌天数
- 听过的歌曲、歌手、专辑数量
- Top 歌曲、歌手、专辑
- 完整播放数量和收听积分
- 主动搜索播放次数
- 主动播放与随机播放比例
- 最常听月份和小时段
- 新增歌曲数量及其收听表现

## 5. 隐私建议

播放统计可以完全本地化：不上传播放记录、不依赖账号，使用 Room 存储，并提供关闭统计和清除统计数据的入口。
