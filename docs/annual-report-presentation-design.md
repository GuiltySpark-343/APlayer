### 0.2 结论

**问题不是「样式不够好看」，而是「体裁选错了」。**

- 我们做的是**仪表盘**：把 21 项指标按顺序堆进一条滚动流，用户负责自己找信息。
- 网易云 / QQ 音乐做的是**叙事流**：一屏一页、一页一个数据主角、配一句情绪文案，用户被带着走。

所以升级重点是**把展示层从 dashboard 改造成 story**：新增一条分页叙事主线，现有仪表盘降级为「数据总览」附录入口（它本身没问题，只是不该当主界面）。

## 1. 调研：两家具体怎么做的

### 1.1 网易云音乐

来源：`docs/research/raw/uisdc-netease2018.txt`（网易 UEDC 动效复盘）、`docs/research/raw/netease-2025-chinadaily.txt`（2025 上线报道）。

**2018 年复盘的核心设计原则（原文提炼）：**

- **情感化设计**：「『报告』是一个听起来挺枯燥的词语，我们希望能通过设计，让文字和数据不那么冰冷严肃。」每页有明确情绪目标——缆车页=轻松旅行，深夜光源页=夜猫子的温暖，骑车页=「专一」但要是「享受」不是「忍受」。
- **不喧宾夺主**：「每一个页面不光有图片、动效，最重要的其实应该是文字和数据。」原版猫尾巴甩得欢，导致视觉焦点分散、用户忽略文案，最后改安静；翻绳游戏动作太复杂，简化为「松弛-紧绷」并降低频次。
- **页面集合是动态的**：「因为每个用户的数据是不一样的，有的页面可能没有展示在你的听歌报告里。」——**数据不足的页直接不出现**。
- **实现选型**：主线用 CSS 动画（不用 GIF/视频/Lottie/SVGA 均有明确论述），位图飘动用精灵图，路径/遮罩用 SVG。

**2025 年（第 9 年）的内容维度：**

| 类别 | 内容 |
| --- | --- |
| 主题 | 「总有一首歌，是为了此刻」；上线前**征集用户建议**决定内容与上线时间 |
| 新增 | 年度音乐四格、年度最爱专辑、最爱歌手榜、年度词曲人、**音乐颜色**、**曲风进化史**、听歌语种、新发行歌曲收听数、曲风制霸（回归）、年度曲风 Top5 |
| 交互创新 | **「年度之最」自主选择**——年度专辑/歌手/单曲可一键更换 |
| 细腻数据 | 每周听歌心情、2025 听歌年历、**5 年深夜听歌对比**、最爱听歌时段、听歌城市 |
| 情感钩子 | 年度歌手来信（专属语音 + 音乐人手绘图） |
| 跨端 | 首创**联合年度报告**（Keep / 逆水寒 / 光遇 / 阴阳师 / 魔兽世界 / 炉石传说） |
| 视觉 | 迷你人物在不同「音乐空间」穿梭；「音乐颜色」= **取用户前 100 张专辑封面颜色**生成专属色板；「年度之最」场景是烟花盛会 |

### 1.2 QQ 音乐（2023，腾讯音乐 MUX 复盘）

来源：`docs/research/raw/uisdc-qq2023.txt`。

**三阶段结构：**

| 阶段 | 做法 |
| --- | --- |
| 看展**前** | 用用户全年数据生成「展览阵容海报」（昵称 + 参展歌手 + 上线时间），提前预告，**并激励数据少的用户在这段时间多听歌攒数据** |
| 看展**时** | 四大主题场馆：独家珍藏（最喜爱歌曲）/ 音乐色彩（四季心情）/ 音乐空间（歌曲排行榜）/ 音乐回忆（历年数据）；**一镜到底**横滑，左右画面拼接（借鉴卷轴画，一步一景）；陀螺仪 + 前/中/后三图层视差 |
| 看展**后** | 纪念票根式总结分享页；年度艺人感谢视频；专属 BGM；留言区 |

**可复用的工程经验：**

- 动效选型用**骨骼动画**（PAG/Lottie「在兼容和素材替换上都不够方便」），并做骨骼压缩 + 级别细分优化性能。
- 视觉流程：**Midjourney 前期批量出图 → 挑选构图合理的 → 预留文案空间 → 建模渲染**。AI 只参与「前期视觉方向」，成品是建模渲染。
- 结果页 KV 从**形 / 色 / 质**三方面做：用图形高度概括关键词（如用音符构成主视觉呼应「千万个音符中的蒙太奇」），渐变灯片做玻璃通透，PS 笔刷做噪点。

### 1.3 提炼：两家共有的骨架

| 环节 | 作用 | 一屏的信息量 |
| --- | --- | --- |
| 开场 / 封面 | 定调、给出年份与主题、播放入口 | 0–1 个数据 |
| 数据主角页（反复 N 次） | 一页只讲一件事，大数字 + 一句人话 | 1–2 个数据 |
| 榜单 / 排行页 | 满足「谁第一」的炫耀与确认 | 3–5 条 |
| 图表页 | 把时间/分布讲成形状 | 1 张图 |
| 关键词 / 人格页 | 把数据翻译成「我是谁」 | 1 个标签组 |
| 分享页 | 可截图、可发朋友圈 | 全部数据的浓缩 |
| 总览 / 附录 | 给数据控自查 | 全部数据 |

**关键洞察：网易云的「音乐颜色」（用户前 100 张专辑封面的主色 → 专属色板）是性价比最高的一招**——它同时产出「一个内容页面」和「整套报告配色」，且**我们本地就有专辑封面**，完全可实现。

## 2. 页面脚本（我们怎么做）

原则：**一页一主角**；数据不足则整页不出现（学网易云）；配色由用户自己的专辑封面主色驱动。

| 编号 | 页面 | 讲什么 | 数据来源 | 布局 | 动效 |
| --- | --- | --- | --- | --- | --- |
| S0 | 开场 | 年份 + 主题词 + 「开始回顾」 | `year` + `ReportStory.keywords` | 全屏渐变 + 大年份 + 关键词 | 淡入 + 背景缓慢流动 |
| S1 | 总览数字 | 今年听了多久 | `listenMs` / `plays` / `listenedDays` | 单个巨大数字占屏 + 两行副数据 | 数字滚动到值 |
| S2 | **音乐颜色** ★ | 你的年度色板 | 专辑封面主色 Top N（新增） | 色卡条带 + 色名 + 一句文案 | 色块依次填充 |
| S3 | 曲风进化史 | 你的口味怎么变的 | 按季度的 `genreBreakdown`（新增序列查询） | 横向时间轴 + 分段色带 | 沿轴推进 |
| S4 | 年度之最 ★ | 年度歌手/专辑/单曲 | `topArtists` / `topAlbums` / `topSongs` | 三段式大卡，各带「换一个」 | 卡片翻入 |
| S5 | 最爱听歌时段 | 你几点听歌 | `hourDistribution` | **24 小时极坐标时钟** | 指针扫过 + 峰值高亮 |
| S6 | 深夜党 | 0–6 点你听了多少 | `hourDistribution` + `lateNightTopSongs` | 暗色版式 + 占比环 | 月亮/光晕呼吸 |
| S7 | 年度年历 | 哪几天在听 | `dailyDistribution` | **年历热力图**（12 行 × 31 列）+ 连续天数 | 格子逐行生长 |
| S8 | 单曲循环王 | 你把一首歌听穿了 | `loopRanking` | 大数字 + 曲名 + 轮次 | 唱片旋转 |
| S9 | 探索 vs 重复 | 你是守旧还是花心 | `repeatRatio` / `discoveryRatio` | 左右对撞双卡 | 卡从两侧推入 |
| S10 | 来源占比 | 你在哪听 | `sourceBreakdown` | 环形图 + 图例 | 弧段生长 |
| S11 | 年度关键词 | 一句话概括你 | `ReportStory` | 标签组 + 人格描述 | 逐个弹出 |
| S12 | 分享页 | 带走它 | 现有海报 | 复用 `ReportPoster` | 由 S11 收拢 |
| S13 | 数据总览 | 全部数据自查 | 现有 `AnnualReportScreen` 全量 section | 保持现状（降级为附录） | — |

**交互形态**：主线用**横向分页 + 一镜到底**（学 QQ 的横滑拼接），而不是纵向长滚动；底部一条细进度指示；支持左右滑动 + 点击前进；`S13` 从 S12 之后的「查看全部数据」进入。

**明确不做**（数据或平台不支持，避免挖坑）：

- 「听歌城市」——无定位数据，且要新增权限，ROI 为负。
- 「联合年度报告」——跨 App 生态合作，非技术问题。
- 「年度歌手来信」——需要音乐人版权内容。

## 4. 图像生成的分工（结论：AI 出图案，代码排版）

### 4.1 分工原则

**扩散模型只负责「图案元素」，排版、文字、数字、图表全部由代码绘制。** 这条边界不可移动。

| 交给 AI（大面积位图） | 交给代码（可缩放矢量 + 文字） |
| --- | --- |
| 背景场景、光斑、渐变光效、纹理/噪点、抽象图案 | icon、分割线、指针、进度条、几何图形、**所有文字与数字** |

理由：

1. **扩散模型的文字渲染不可靠，中文尤其差**，模型倾向于「忽略文字、改成画一幅相关的自然图像」或产出畸形字形（[中文文字乱码分析](https://tudingai.cn/blog/202607/gpt-image-2-chinese-text-garbled-workarounds/)、[文本渲染综述](https://arxiv.org/pdf/2505.18985v2)）。报告里必须精确出现的是数字、曲名、歌手名、日期——**错一个字就废**。
2. **业界与学术界给出的正解就是这个分工**：[PosterVerse（AAAI）](https://ojs.aaai.org/index.php/AAAI/article/view/37656/41618) 这类商用海报框架的结论是「HTML/代码负责可缩放的排版，扩散模型负责图像内容」；[Code or diffusion 实践指南](https://dev.to/aws-builders/code-or-diffusion-a-field-guide-to-programmatic-image-generation-2jm7) 讨论同一取舍。
3. **小图标交给扩散模型是负收益**：糊边、不可缩放、改色要重出，不如矢量绘制。

### 4.2 硬件与运行位置

- **16 GB 显存足够**出图（[FLUX.1-fp8 16G 部署](https://blog.csdn.net/weixin_42128315/article/details/157676614)、[ComfyUI 显存指南](https://comfyui-wiki.com/zh/install/install-comfyui/gpu-buying-guide)）：SDXL 全流程有富余；Flux.1-dev 用 fp8 量化可跑 1024×1536。
- **只作为开发期资产生产线，绝不在运行时于手机生成**：算力、耗电、包体都不允许。产出物是打进 `res/drawable-nodpi/` 的静态资源。

## 5. 视觉资产与模板分层方案

### 5.1 四层架构（代码里必须真分层）

```
Layer 0  底图         AI 产出，无文字、无 UI、无边框
Layer 1  scrim/蒙版   代码绘制，保证文字对比度
Layer 2  文字与数字   代码绘制，模板固定坐标
Layer 3  矢量装饰     icon / 分隔线 / 指针 / 进度，代码绘制
```

**红线**：任何情况下不允许把文字烘进底图。底图永不包含可读字符。

### 5.2 灰度底图 + 代码染色（最重要的工程优化）

让 AI 只出**明度结构**（灰度/单色），运行时由代码按用户主色做 duotone/overlay 染色。

收益：

- 资产量从 `N 页 × M 种用户配色` 降到 `N 页`
- 每份报告配色依然独一无二（呼应「音乐颜色」）
- 页面与海报自动同源（同一份 token 染色）

### 5.3 底图数量：4–6 张 × 参数化，而不是 13 页 13 张

13 张独立出图几乎必然画风飘移，且包体膨胀。策略：**4–6 张底图 × 参数化变换**（旋转/缩放/裁切/翻转/噪点/染色）覆盖 13 页。

体积预算：1080×1620 WebP q80 ≈ 150–300 KB/张；控制在 **≤4 MB**，首屏用原图、次要页可按需。

### 5.4 卡片模板（"固定位置写字"的落点）

定义有限个模板，每页绑定一个；模板 = 一组坐标常量 + 一组文字槽。这样"固定位置写字"就是「模板 + 数据」，可复用、可回归测试。

| 模板 | 结构 | 用于 |
| --- | --- | --- |
| `HeroCenter` | 居中巨数字 + 上下小字 | S1、S8 |
| `SplitMedia` | 左图右数 / 上图下数 | S2、S6 |

### 5.5 文字槽契约（固定坐标的硬约束）

固定坐标 + 动态内容 = 溢出风险（现海报 B2 就是实例）。每个文字槽必须声明：

| 字段 | 含义 |
| --- | --- |
| `rect` | 相对画布的比例或绝对坐标（推荐比例，便于多分辨率） |
| `maxWidth` / `maxLines` | 边界 |
| `minTextSize` | 缩字下限 |
| `overflow` | 超过下限后的行为：省略号 / 换行 / 丢弃 |
| `align` | 左 / 中 / 右 与基线锚点 |
| `avoidHeadChars` | 是否启用中文避头点 |

**验收手段**：极端数据回归——最长歌名、5 位数播放次数、4 位数小时数、超长歌手名，渲染后人工看图确认无溢出、无行首标点。

### 5.6 自动 scrim 算法（保证白字不压亮斑）

底图明暗不可控，因此 Layer 1 不是可选：

1. 取文字槽矩形覆盖的底图区域，按网格采样（如 8×8）算平均亮度与亮度方差；
2. 亮度高于阈值 → 加深色 scrim、文字转深色；否则白字 + 轻 scrim；
3. scrim 强度按方差上调（明暗跳变剧烈的区域要多压一点）；
4. 结果缓存，避免每帧重算。

### 5.7 出图纪律

- `negative: text, letters, numbers, watermark, logo, signature, ui, frame, border`
- `positive` 中固定声明**留白要求**（给文字槽预留安全区）
- 一致性靠**锁死模型 + seed 族 + style prompt**，只变 subject（夜猫子→夜景；摇滚→霓虹；古典→剧院帷幔）
- 可按关键词/曲风选底图，形成「音乐颜色」之外的第二个性化维度
- 出图 → 挑图（人工）→ 转 WebP → 落 `res/drawable-nodpi/report_<template>_<variant>.webp`

### 5.8 履约顺序

```
定模板 → 出 1 张灰度底图 → 染色 → 固定坐标写字
→ 极端数据渲染 → 人工看图确认 → 再复制到其余页
```

**先跑通 1 页**（建议 S1，结构最简单）再批量，避免出完 13 张才发现画布比例或安全区要改。
